# RMR Platform v5.1 RC1 Application Change Log

**Original release:** `5.1.0-rc1`  
**RC2 status:** all application changes in this document are preserved unchanged in `5.1.0-commercial-cb1`.  
**Baseline:** `5.0.0-rc1`  
**Release purpose:** functional client experience, tenant workflow, navigation, permissions, recovery, upgrade preservation and QC correction. No unrelated module expansion was added.

## Authentication and first-run setup

- Widened and balanced first-run setup for large monitors while retaining tablet/mobile responsiveness.
- Clarified RMR Owner versus optional Step2 Platform Administrator fields.
- Normalized setup/login email handling.
- Verified the owner password hash and persisted credentials before setup can succeed.
- Automatically signs the RMR Owner in after successful setup.
- Invalidates the one-time setup token and removes `data/INITIAL-SETUP.txt` after success.
- Added browser Forgot Password and one-time reset-token flows.
- Added expiring, single-use invitation and reset tokens stored only as hashes.
- Added masked `python -m rmr_platform.cli recover-owner --email ...` pilot recovery.
- Added local pilot recovery-link files where SMTP is not configured.

## Windows and Linux installation/upgrade

- Made `INSTALL.bat` the supported Windows double-click launcher and preserved the console through success/failure.
- Added separate `INSTALL-PRODUCTION.bat` and `INSTALL-DEMO.bat` entry points.
- Strengthened Docker/Compose/engine validation and browser launch in `INSTALL.ps1`.
- Added `UPGRADE-FROM-V5.0.ps1`, `.bat`, and `.sh` with safety backup, additive migration, data copy, health validation and failure return to the untouched v5.0 installation.
- Updated install profiles and container version to `5.1.0-rc1` in the original RC1 release. RC2 supersedes only the upgrade/deployment gate.

## Client creation, invitations and access

- Replaced opaque client key/temporary-password behavior with secure Client Administrator invitations.
- Added structured field-level duplicate-email and duplicate-slug errors.
- Preserved Add Client form state after validation errors.
- Added dirty-form-safe modal behavior.
- Added invitation lifecycle: pending, accepted, revoked, expired, resend and activation history.
- Added client access summaries, pending invitation details and last-login visibility.
- Added Client Administrator user creation through invitation rather than administrator-known passwords.
- Added client-side activation page where the client sets their own password.

## Multi-tenant navigation and tenant isolation

- Consolidated Portfolio, tenant selector, Onboarding, Pricing and Client 360 on one canonical persisted tenant source.
- Refreshes selectors and dashboards immediately after client creation and onboarding mutations.
- Added global Back control and breadcrumbs.
- Added explicit Return to Portfolio controls on Client 360 and workflow screens.
- Added notification deep links to the relevant client/workflow.
- Completed separate client shell/navigation: client users see only their tenant and authorized services.
- Preserved server-enforced denial of cross-tenant access.

## Client 360 and support governance

- Expanded Client 360 into a clear relationship/administration launch point.
- Added Edit Client Details, Manage Client Access, Client Pricing, Onboarding, Website and read-only operational actions.
- Distinguished metric states such as Not measured, Not assigned, Not configured and No records yet.
- Added metric provenance/state instead of implying poor performance from absent data.
- Preserved RMR/Step2 read-only support access to CRM, forecast and other client-owned operations.
- Preserved support-access audit records.

## Onboarding

- Renamed stage 2 to **Tenant provisioning & client access** while preserving the eight-stage operating model.
- Added client-access status and management inside onboarding.
- Enforced active Client Administrator as a go-live gate.
- Returned fresh onboarding and dashboard data after every save/complete action.
- Updated progress immediately through 13/25/38/50/63/75/88/100 percent.
- Added final completion state with Return to Onboarding, Return to Portfolio and Open Client 360 actions.
- Preserved all v5.0 onboarding notes and structured data through additive migration.
- Corrected clipboard behavior across step transitions.

## Client CRM, forecast and role permissions

- Added invitation-based client user administration.
- Preserved client editing of authorized CRM, forecast, activities, campaigns and personnel records.
- Preserved global-admin read-only enforcement for client operational data at the API layer.
- Added tenant-aware client navigation and service entitlements.
- Added objective cross-tenant isolation tests.

## Solutions Center and notifications

- Simplified client-facing service states to Available, Requested, Pending Activation and Active.
- Removed unnecessary internal RMR/Step2 review/process language from client copy.
- Added solution-interest signals and explicit solution requests.
- Added actionable RMR/Step2 notifications and expansion-request queue entries.
- Prevented billing/entitlement changes before activation.
- Synchronizes activated services, Client Pricing, entitlement and required training after approval.

## Partner Economics and costs

- Added governed cost categories for hosting/infrastructure, software/API, payment processing, staff/labor, client support, sales commission, general operating and other direct costs.
- Added direct client/service, client-level and shared portfolio cost entries.
- Added effective-dated cost-allocation rules.
- Added equal-client, revenue-share, direct and policy-pending allocation bases.
- Separated transaction direct costs, additional direct costs, allocated shared operating costs and unallocated policy-pending costs.
- Added contribution after allocated costs while preserving existing RMR/Step2 transaction split evidence.
- Kept unresolved accounting policy under RMR control rather than silently choosing a rule.

## System Health and empty states

- Added a plain-language business headline, business impact and recommended action.
- Preserved technical checks below the business summary.
- Added role-aware guidance to empty fresh-install workspaces.

## Data model and API

- Added `UserInvitation`, `PasswordResetToken`, `CostCategory`, `CostAllocationRule` and `CostEntry` models.
- Added Notification deep-link/entity fields.
- Added migration `005.001.000-functional-client-experience`.
- Added invitation, password-reset, cost, allocation and client-access APIs.
- Updated generated OpenAPI and SQLite schema references for v5.1.

## Testing and evidence

- Added dedicated v5.1 API/permissions/end-to-end acceptance suite.
- Added browser workflow and responsive suite including 1920×1080, 1440×1050 and mobile evidence.
- Added authoritative v5.0→v5.1 preservation test.
- Added backup/restore test.
- Added healthy/degraded System Health messaging test.
- Added v5.1 static/source/installer audit.
- Added completed QC matrix, role/permission summary, manual QC sequence, known issues and upgrade/rollback documentation.
