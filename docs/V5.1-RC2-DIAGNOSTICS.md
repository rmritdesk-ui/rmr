# v5.1 RC2 Diagnostic and Failure Reporting Guide

## Automatic diagnostics

If the Windows upgrade does not become healthy, RC2 automatically creates a text file under:

```text
data\diagnostics\
```

The console displays the exact file path. It also writes:

```text
data\LAST-UPGRADE-RESULT.json
```

Send both files to RMR/ChatGPT. No Docker commands need to be interpreted manually.

## What the diagnostic contains

- release and timestamp;
- safe non-secret environment values;
- container state, restart count and Docker health;
- host and internal health results;
- bounded polling history;
- Docker and Docker Compose versions;
- `docker compose ps -a` output;
- application maintenance status;
- recent application container logs.

The collector intentionally excludes `RMR_SECRET_KEY`, setup tokens, passwords and live credentials.

## Manual collection

When the application is running but a deployment issue needs investigation, double-click:

```text
COLLECT-DIAGNOSTICS.bat
```

The resulting file appears in `data\diagnostics`.

Linux:

```bash
./COLLECT-DIAGNOSTICS.sh
```

## Failed upgrade behavior

If RC2 fails its bounded health gate:

1. diagnostics are captured before the RC2 container is removed;
2. RC2 is stopped;
3. the untouched v5.0 installation is restarted;
4. v5.0 is independently health-checked;
5. the rollback result is written to `LAST-UPGRADE-RESULT.json`.

Do not modify source code or database files. Return the diagnostic evidence to RMR for a new versioned correction.
