# RMR Platform v5.1 Commercial Candidate Rollback

## Automatic upgrade rollback

The v5.0-to-RC3 upgrade keeps the v5.0 folder and data untouched. If RC3 fails its readiness gate, the upgrade script automatically:

1. captures RC3 diagnostics;
2. stops/removes only the RC3 container;
3. starts the original v5.0 installation;
4. polls v5.0 until container, internal API, host API, Docker health and version checks pass;
5. records the result in RC3 `data\LAST-UPGRADE-RESULT.json`.

A successful automatic rollback reports:

```text
The previous v5.0 installation is running and healthy.
```

## Manual rollback after a successful RC3 upgrade

Use this only if RC3 installed successfully but later manual QC requires returning to v5.0.

1. Stop RC3 from the RC3 folder:

```powershell
.\STOP.ps1
```

2. Open the original v5.0 folder.
3. Start v5.0:

```powershell
.\START.ps1
```

4. Confirm `http://localhost:8080` opens and your v5.0 data is present.

The original v5.0 data is authoritative for rollback because RC3 upgrades a copy. New records entered only in RC3 after upgrade will not exist in v5.0 unless separately exported/migrated.

## Diagnostic evidence

If rollback does not become healthy, use RC3:

```text
COLLECT-DIAGNOSTICS.bat
```

Send the generated file and `data\LAST-UPGRADE-RESULT.json` to RMR/ChatGPT. Do not edit source or database files.
