# RMR Platform v5.1 Commercial Candidate Change Log

**Release:** `5.1.0-commercial-cb1`  
**Baseline:** `5.1.0-rc2`  
**Scope:** Windows/Docker preflight version-compatibility correction only. All RC1/RC2 application functionality, tenant workflows, permissions, data models, diagnostics and rollback controls are preserved.

## Real Windows evidence that triggered RC3

The first RC2 Windows preflight did not modify v5.0, but it incorrectly rejected the running v5.0 installation as unhealthy. RC2 diagnostics proved that v5.0 was healthy from the first readiness attempt:

- container status: `running`;
- Docker health: `healthy`;
- restart count: `0`;
- host health: HTTP 200 / `healthy`;
- internal health: `healthy`;
- expected version from v5.0 `.env`: `5.0.0-rc1`;
- version reported by the running v5.0 health endpoint: `5.0.0-rc.1`.

The literal version comparison prevented readiness from succeeding even though every operational health signal passed.

## RC3 correction

- Added `ConvertTo-RmrComparableVersion` to normalize only the known v5.0 metadata pair `5.0.0-rc1` and `5.0.0-rc.1`.
- Added `Test-RmrVersionCompatible` and routed readiness validation through it.
- Kept exact comparison behavior for all other versions. For example, `5.1.0-commercial-cb1` is **not** treated as equivalent to `5.1.0-rc.3`.
- Requires host and internal health endpoints to agree after normalization.
- Added comparable host/internal/expected versions and a `version_compatible` flag to readiness-attempt diagnostics.
- Preserved RC2 bounded polling, transient Windows HTTP retry behavior, container-state gates, diagnostic capture, verified rollback, safety backup and additive migration flow.
- Updated release metadata to `5.1.0-commercial-cb1`.
- Added regression coverage reproducing the exact RC2 field failure and proving it now passes on the first modeled readiness attempt.

## Not changed

No product workflow, UI, database schema, permissions, tenant isolation, Client 360, CRM, onboarding, Client Pricing, Partner Economics, training, website, campaign, ProspectIQ, backup/restore or client-activation behavior was redesigned for RC3.

## Certification boundary

RC3 is source-tested and modeled in the build environment. The exact RC3 ZIP still requires the external Windows Docker Desktop upgrade test against the user's untouched v5.0 installation before Hasan/Step2 handoff.
