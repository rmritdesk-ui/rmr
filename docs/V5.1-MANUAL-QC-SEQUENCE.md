# RMR Platform v5.1 Commercial Candidate Manual QC Sequence

Use this sequence after installing or upgrading the exact v5.1 Commercial Candidate ZIP. Do not edit source files or database records to make a test pass.

## A. Install / first-run setup

1. Verify the ZIP SHA-256.
2. Extract into a new permanent folder.
3. Start Docker.
4. Windows: double-click `INSTALL-PRODUCTION.bat`; Linux: run `./INSTALL.sh empty`.
5. Confirm the installer window remains visible and ends with a success/failure summary.
6. Confirm the browser opens to the first-run setup screen.
7. At 1920×1080 and normal browser zoom, confirm the setup form is readable and not compressed.
8. Enter the one-time token from `data/INITIAL-SETUP.txt`.
9. Create the RMR Owner with a unique email/password. Defer Step2 creation or create it with a different unique email.
10. Confirm setup signs the owner in automatically.
11. Confirm `data/INITIAL-SETUP.txt` has been removed.
12. Sign out and sign back in with the exact owner credentials.
13. Use Forgot Password and confirm a one-time reset link is produced/delivered according to configuration.

## B. Create and provision the CAF test client

14. From Portfolio Command Center, select **+ Add New Client**.
15. Enter CAF company/contact data, select services, prices and website mode.
16. Deliberately enter an email already in use and submit.
17. Confirm the error appears at the email field and the modal remains open with every other value preserved.
18. Correct the email and create CAF.
19. Confirm no opaque tenant key or administrator-known temporary password appears.
20. Copy the Client Administrator activation link if local recovery mode is enabled.
21. Confirm CAF appears immediately in Portfolio, tenant selector, Client Onboarding, Client Pricing and Client 360.

## C. Activate the CAF Client Administrator

22. Open the activation link in a private/incognito browser window.
23. Confirm the page identifies CAF and the invited Client Administrator role.
24. Set a password and activate the account.
25. Confirm the client portal opens automatically.
26. Confirm the client sees only CAF and cannot see Portfolio Command Center, other clients, Client Pricing administration or Partner Economics.
27. In the RMR session, open Notifications and confirm CAF activation notification deep-links to CAF Client 360.
28. In CAF Client 360, confirm Client Access shows the active Client Administrator and last-login status.

## D. Complete onboarding

29. Open CAF onboarding.
30. Confirm eight stages exist and stage 2 is **Tenant provisioning & client access**.
31. Copy text from a field in one step, advance and paste it in the next step.
32. Complete stages 1–7 and confirm progress updates immediately after each stage.
33. Before client activation, verify Go-Live Validation is blocked. After activation, verify it can complete.
34. Complete stage 8.
35. Confirm the completion screen offers Return to Onboarding, Return to Portfolio and Open Client 360.
36. Choose Return to Onboarding and confirm CAF shows 100% immediately.
37. Reopen CAF onboarding and confirm notes and completed states persist.

## E. Client operations and tenant isolation

38. In the CAF client session, open CRM.
39. Create one account, contact, opportunity and activity.
40. Create/update a forecast entry.
41. Confirm the client can edit those records.
42. Create a second test tenant from RMR.
43. Attempt to access the second tenant with CAF credentials using UI and direct URL/API where practical; confirm denial.
44. In RMR, open CAF Client Operations — Read Only.
45. Confirm RMR can inspect CAF records but cannot create/edit/delete client CRM or forecast records.
46. Confirm Support Access Audit records the authorized read-only view.
47. Use the global Back control/breadcrumb to return to CAF Client 360 and Portfolio without browser Back.

## F. Website and Solutions Center

48. Open CAF Website from Client 360.
49. For a managed website, confirm preview opens and does not use a broken local-file path.
50. Edit an allowed website configuration as the appropriate client role and confirm preview updates.
51. In CAF Solutions Center, explore an available solution.
52. Confirm exploration alone creates no charge or entitlement.
53. Submit **Request This Solution**.
54. In RMR, confirm a notification and Service Request appear with a deep link.
55. Set to Pending Activation, then activate it.
56. Confirm Client Pricing, entitlement and required training synchronize only after activation.

## G. Partner Economics and System Health

57. Add one direct client/service cost.
58. Add one shared portfolio cost with an approved allocation basis.
59. Add one policy-pending cost.
60. Confirm the report separates direct, allocated and policy-pending costs and does not silently allocate pending policy.
61. Open System Health.
62. Confirm the top message explains business impact and recommended action in plain language.
63. Confirm technical checks remain available below.

## H. Backup, restore and upgrade

64. Create a backup.
65. Create a clearly named post-backup test client/record.
66. Restore the backup and confirm the post-backup record is removed while pre-backup records remain.
67. On Windows Docker Desktop, leave the real v5.0 folder intact, extract RC3 separately and run `UPGRADE-FROM-V5.0.bat`.
68. Confirm the command window shows bounded readiness progress rather than failing on the first transient HTTP error.
69. Confirm success is not reported until container, Docker health, internal API, host API, exact-version and application-status checks pass.
70. Confirm client records, CAF onboarding notes, service schedules and negotiated prices survive.
71. Confirm `data\LAST-UPGRADE-RESULT.json` reports `success`.
72. For rollback validation, use a controlled failed-upgrade test only on a disposable copy. Confirm diagnostics are written before rollback and the untouched v5.0 installation is restarted and independently health-checked.
